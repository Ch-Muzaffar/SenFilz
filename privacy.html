Privacy Policy

Last updated: September 2026

1. What we collect

Our signaling server receives your IP address as part of normal WebSocket connections. This is used transiently for rate limiting (to prevent abuse) and is held only in memory — it is never written to a database or log file, and is discarded when the session ends or the server restarts.

We do not use cookies. We do not use analytics by default. We do not create user accounts or profiles of any kind.

2. What we don't collect

The following information never reaches our servers:

  • File names
  • File contents
  • File sizes
  • File types
  • Any metadata about the files you transfer

This is not a policy choice — it is a technical fact. Files transfer directly between two browsers using WebRTC data channels. Our server is never in the data path.

3. How transfers work

When you generate a transfer code, your browser connects to our signaling server via WebSocket. The server generates a 6-digit code and stores a small in-memory record linking your connection to that code. This record holds only the WebRTC connection metadata (SDP offer/answer and ICE candidates) — not your file.

When the receiver enters the code, the server forwards the connection metadata to their browser. The two browsers then establish a direct WebRTC connection. From that point on, all data transfers directly between the two browsers. The session record is deleted immediately after the receiver connects, and all remaining records expire automatically after 10 minutes.

4. IP addresses and WebRTC

WebRTC peer-to-peer connections work by exchanging network information (ICE candidates) between the two peers. This process may expose each peer's IP address to the other — this is how WebRTC works at a network level and cannot be avoided for direct connections.

We do not claim that SenFilz transfers are anonymous or untraceable. Both the sender and receiver can see each other's IP addresses as part of normal WebRTC operation. Do not use SenFilz if IP address visibility between peers is a concern for your use case.

When a TURN relay server is used (as a fallback on restrictive networks), file data passes through the relay — but still encrypted by WebRTC's mandatory DTLS encryption. The relay server (provided by Metered.ca) does not have access to the plaintext of your file data.

5. Third-party services

SenFilz uses the following third-party services:

  • Google STUN server (stun.l.google.com:19302) — used to help establish peer-to-peer connections. Your IP address is disclosed to Google as part of this process. See Google's Privacy Policy.
  • Metered.ca TURN server — used as a relay fallback on restrictive networks. See Metered's Privacy Policy.
  • Google Fonts — used to load the Inter typeface. Google may log your IP address when the font is requested. See Google's Privacy Policy.
  • cdnjs (Cloudflare) — used to load the QR code library. Cloudflare may log your IP address when the script is requested.

6. Data retention

Transfer session records (in-memory only): deleted immediately when the receiver connects, or automatically after 10 minutes if unused.

IP addresses for rate limiting (in-memory only): discarded when the server restarts or after the rate-limiting window (60 seconds) passes with no new activity from that IP.

We have no persistent data storage. There is nothing to delete on request because nothing is retained.
