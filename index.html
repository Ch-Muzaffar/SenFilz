How it works

Three steps. No account required.

1

Drop your file

Select or drag one or more files. A 6-character code and QR code appear instantly. The code is valid for 10 minutes.

2

Share the code

Send the 6-character code to the receiver over any channel — chat, email, voice. They can also scan the QR code to open directly on another device.

3

Files transfer directly

The receiver enters the code and the file streams straight from your browser to theirs via WebRTC. Nothing touches our servers.

FAQ

Common questions

Does SenFilz store my files?

No. Files transfer directly between the two browsers using WebRTC data channels. Our signaling server only relays the connection details needed to set up that direct link — it never sees, receives, or touches your file data.

Are transfers private?

The connection is peer-to-peer, so files go directly between the two browsers. As with any direct internet connection, both sides can see each other's IP address — this is standard WebRTC behaviour and cannot be avoided without a relay (TURN) server. We do not log or store any transfer data on our end.

How many files can I send at once?

You can drop multiple files at once. They will be sent sequentially over the same connection — each one downloads automatically on the receiver's side as it finishes. One transfer code covers all selected files.

What is the file size limit?

There is no hard limit enforced by SenFilz. However, very large files (above 2 GB) are held in the browser's memory during transfer. On devices with limited RAM this can cause the browser to crash. For very large files, we recommend splitting them or using a dedicated large-file transfer service.

Does transferring change my files in any way?

No. WebRTC data channels transfer raw binary data — the file on the receiver's device is byte-for-byte identical to the original. There is no compression, re-encoding, or modification of any kind.

How long does the code last?

Each code is valid for 10 minutes and can only be used once. As soon as a receiver connects, the code is immediately invalidated so no one else can join the session.

Why did my transfer fail?

WebRTC direct connections can fail on restrictive networks — corporate firewalls, certain VPNs, or university networks that block peer-to-peer traffic. SenFilz uses both STUN (for NAT traversal) and TURN (as a relay fallback) to improve reliability, but some networks block all of these. Switching to a mobile hotspot or a different network usually resolves the issue.

Does it work on mobile?

Yes. SenFilz works in any modern browser on iOS and Android — no app required. The receiver can also scan the QR code directly with their phone camera to open the receive page automatically.
